# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

BrightPath parent app: Expo SDK 57 / React Native, Expo Router (typed routes), TypeScript (strict), React Compiler. Targets iOS, Android, and web. Parents see their child's AI lesson summaries, activities, calendar and notifications. The backend is a separate repo (`brightpath-server`, Express + MySQL). In development the app calls port 3000 on the machine running Metro (web: the page's host; native: `Constants.expoConfig.hostUri`), so it survives LAN IP changes; set `EXPO_PUBLIC_API_URL` in `.env` to override, and always (with https) for production builds. See [AGENTS.md](AGENTS.md) for the Expo-specific rules (do not trust memorized Expo APIs; check the versioned docs before touching Expo/EAS/RN APIs).

## Commands

```bash
npx expo start              # dev server (also: npm run android | ios | web)
npx expo lint               # lint (npm run lint)
npx tsc --noEmit            # typecheck (typed routes in .expo/types are regenerated by `expo start`)
npx expo-doctor
npm test                    # Jest unit tests (npm run test:watch while developing)
npx expo install <package>  # always use this to add deps, not npm add
```

Run lint, typecheck and `npm test` before declaring a task done.

**Tests**: Jest with `jest-expo` and React Native Testing Library v14 (its `render`/`renderHook`/`act` are async — always `await` them). Test files go in `__tests__/` folders as `*.test.ts(x)`, never inside `src/app/` (every file there is a route). `src/test-utils/api-mock.ts` fakes the API (`mockApi({ 'GET /me': () => json(200, meBody()) })`); mock `@/services/storage` in tests that touch the session. `expo-secure-store` is native code, so use a development build rather than Expo Go if it misbehaves.

## Architecture

- **Roles**: parent, teacher, admin (school admin), super_admin (from `user.role` / `user.status` / `user.school` in `context/auth-context`, plus `permissions` for school admins). Root `_layout.tsx` mounts one `Stack.Protected` group per role: parents get `(tabs)` + detail screens; active teachers get `teacher/*` (dashboard, lesson/activity editors where `[id]` = `new` creates; archive/restore instead of delete); school admins get `admin/*` (their school only; tabs/actions gated by `permissions`); super admins get `super/*` (schools, admin approval/permissions, all users); non-active accounts get `pending`. `settings` is shared. The server enforces the same rules — these guards are UX only.
- **Pendants** (lesson-recording devices): one per teacher. Teachers see their own on the dashboard (`components/pendant-status`); school admins manage them on the Pendants tab and a teacher's user page. Never show pendant data to parents — its online/sync status reveals when a class is being recorded.
- **No deletes**: the UI never offers delete. Use disable (users), inactive (students), archive (sections, lessons, activities), deactivate (schools).
- **Routes** (`src/app/`): root `_layout.tsx` sets up providers (React Query → Settings → Auth → Child) and the guarded `Stack`; `sign-in`/`sign-up` (Parent / Teacher / School admin; the latter two pick a school from the public `/schools` list) when signed out. `(tabs)/_layout.tsx` renders `components/app-tabs` — `app-tabs.tsx` (NativeTabs, `expo-router/unstable-native-tabs` in SDK 57) and `app-tabs.web.tsx` (headless `expo-router/ui` bottom bar). Tab names must stay in sync across both files and the `(tabs)` route files. Detail routes are `lesson/[slug]` and `activity/[slug]`; navigate with `router.push({ pathname: '/lesson/[slug]', params: { slug } })`.
- **Data layer**: `services/api.ts` is the only `fetch` wrapper (adds bearer token, 20s timeout, maps errors to `ApiError` with the server's `code`, signs out on 401, reloads `/me` on account-state 403s, and drops responses that arrive after the signed-in identity changed). Use `errorMessage(e)` to show errors.
- **Sessions**: tokens are bound to server-side sessions. Sign-out calls `/auth/logout` (revokes the token) and cancels/clears every query; tokens older than a day are renewed via `/auth/refresh` on launch; the profile reloads when the app returns to the foreground. If the server is unreachable at launch the saved session is kept and a retry screen is shown (never sign out on network errors). `services/brightpath.ts` lists every endpoint; `hooks/queries.ts` wraps them in React Query hooks. All child-scoped keys start with `['child', id]` so mutations invalidate per child. Response types are in `types/api.ts` and must mirror the server's mappers.
- **State**: `context/auth-context` (token + parent + children; token in SecureStore via `services/storage.ts`, sessionStorage on web via `storage.web.ts`), `context/child-context` (which child is being viewed; `useChildId()` for queries), `context/settings-context` (theme override, text size, high contrast, reduce motion; persisted locally).
- **Theming**: `constants/theme.ts` tokens; `useTheme()` applies the settings override and high contrast; `ThemedText` applies the text-size scale. Use theme tokens and `ThemedText` types rather than hard-coded colors/sizes. Shared primitives live in `components/ui/`, domain components (lesson/activity cards, child switcher) in `components/`.
- **Dates**: API dates are local wall-clock strings — always parse with `utils/format.ts` `parseDate`, never `new Date(string)`.
- **Security**: notification links are only followed if they match the in-app allow-list in `app/notifications.tsx`. Never log or persist the token outside `services/storage`.
- **Native config**: no `ios/`/`android/` dirs (CNG); configure via `app.json` and config plugins.
